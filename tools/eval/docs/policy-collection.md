# 수집 정책 (policy-collection)

> 근거: PRD 「데이터 모델 & 사용자 입력」「저장소 배치 (D1)」「시계열 (D1-a)」, TODO 「M2 착수 전 결정」「업적 데이터」.
> 이 문서에 결정으로 적힌 내용만 다룬다. 없는 규정은 만들지 않는다.

## 1. 데이터 계층

제1조 (2계층 분리) 이 도구의 데이터는 객관 데이터와 주관 데이터로 나뉘며, 두 계층을 섞지 않는다.

| 계층 | 성격 | 예시 필드 | 입력 방식 |
|---|---|---|---|
| 객관 데이터 | API가 긁어오는 사실 | 보유 게임, 플레이타임, 업적 달성률, 완주 여부, 플랫폼, 장르 태그, 마지막 플레이일 | 자동 수집 |
| 주관 데이터 | 사용자만 남길 수 있는 평가 | 별점, 한줄평, 상태, 기피 사유 | 수기 입력 |

제2조 (source 태그) 모든 게임 엔트리는 `source` 필드를 갖는다. `auto`(자동 수집) 또는 `manual`(수기 추가) 중 하나이며, 재동기화 병합의 분기 기준이 된다.

## 2. 재동기화 병합 규칙

제3조 (객관 필드 덮어쓰기) `source: auto`인 게임의 객관 필드는 재동기화 시 API 최신값으로 갱신한다. 덮어써도 된다.

제4조 (주관 필드 불변 보존) 별점 등 주관 필드와 `source: manual` 엔트리는 재동기화 시 절대 덮어쓰지 않으며 건드리지 않는다.

제5조 (수기 게임 추가) 자동 수집에 잡히지 않는 게임(PSN·엑박 구작, 비연동 플랫폼)은 사용자가 직접 추가한다. 메타 DB(IGDB/RAWG) 검색으로 게임을 찾아 제목·커버·장르 등 메타데이터를 채우고, 이렇게 추가된 엔트리는 `source: manual`이 되어 재동기화에도 보존된다.

## 3. 저장소 배치

제6조 (정본과 파생) `library.md` 인덱스 1개가 객관 데이터의 정본이다. `games/*.md`는 전 게임을 유지하되, 그 안의 객관 필드는 `library.md`에서 파생된 사본이므로 재동기화 때 덮어쓴다. 주관 필드(`rating`·한줄평·기피 사유)만 게임 노트가 정본이며 절대 보존한다.

| 파일 | 읽는 주체 | 성격 | 재동기화 |
|---|---|---|---|
| `library.md` 1개 | 기계 | 객관 데이터 정본. 전 게임 × 전 축 테이블 | 통째 재생성 |
| `games/*.md` | 사람이 쓰고 기계가 읽음 | 주관 데이터의 그릇 | 필드 단위 분기(제3·4조) |
| `reports/*.md` | 사람 | analyze 산출물 | 누적 |
| `history.jsonl` | 기계 | 스냅샷 로그 (정본 아님, 재생성 불가) | append only |

제7조 (전수 유지) 게임 노트는 일부만 만들지 않고 전 게임을 유지한다. 기계가 전수를 읽는 이상 개수를 줄이는 이득이 없고, 노트가 없는 게임에 나중에 별점을 매길 때 생성 분기가 하나 더 생기기 때문이다.

## 4. 스냅샷 로그

제8조 (history.jsonl) `gather` 실행마다 `{ts, appid, playtime}` 스냅샷을 append only로 기록한다. 현 설계가 스냅샷 덮어쓰기라 "지난달 대비 변화"를 분석할 수 없으므로, 축적은 되돌릴 수 없어 M2에 포함한다. md가 정본이라는 원칙과는 부딪히지만, 로그 계층(정본도 아니고 사람이 읽는 문서도 아님)으로 예외 처리한다.

## 5. 업적 데이터 수집 제약

제9조 (403 실패 사유) `GetPlayerAchievements`는 API 키·SteamID가 정상이어도, Steam 프로필의 "게임 세부정보" 공개 설정이 꺼져 있으면 403(`Profile is not public`)으로 전량 실패한다. 이는 코드 문제가 아니다. gather는 게임별 실패 시 업적 없이 계속 진행하므로 수집 자체는 안전하다.

제10조 (채택된 해결) 업적 데이터 확보 방법은 프로필 설정을 공개로 전환하는 것(A안)으로 채택한다. 코드 0줄로 전수 해결된다. 로컬 캐시 파싱·Steamworks 로컬 API·`node-steam-user`·대체 엔드포인트 등은 리서치 후 탈락 또는 백로그로 이연되었으며, 이 문서의 수집 정책이 아니다.

## 6. 수집 범위

제11조 (현재 수집원) M2 시점의 자동 수집원은 Steam이다. 위시리스트는 `IWishlistService/GetWishlist/v1`로 전수 조회하고, 게임 메타(장르·키워드·플랫폼)는 Steam `appdetails`로 조회한다. 외부 메타 DB 선정은 M4 착수 전으로 이연되었고 1순위는 IGDB다.

제12조 (시점 이연 — 지금은 수집하지 않는다) PSN·Xbox 커넥터는 M4 이후이며, 스파이크 검증 전에는 수집하지 않는다. 가격 정보도 여기 속한다 — Steam `appdetails` 응답에 `price_overview`(통화·정가·할인가·할인율)가 함께 오므로 기술적으로는 추가 키·로그인 없이 지금도 수집 가능하지만, 현재 수집 대상에 넣지 않았다. 가격이 시점 데이터라 "md가 정본"이라는 저장 원칙과 결이 다르고(노트에 박으면 하루 만에 낡는다), 실시간 조회로 다룰지 로그 계층에 스냅샷으로 쌓을지가 아직 정해지지 않았기 때문이다. 따라서 가격 문의에는 "현재 데이터에 없다"고 답하고 넘긴다. "다룰 수 없는 주제"라고 답하지 않는다.

제13조 (영구 제외 — 전략적 결정) 범용 미디어 트래커화(영화·책·애니 등 타 도메인)는 게임 특화 전략상 명시적으로 제외한다.
